场景网格：Scene-N1 的 MP3D（队友下载的 `mp3d_n1.tar.gz`，只读），用 trimesh 转成 GLB（[convert_scene.py](https://github.com/fanxinyusarah/lewm-navigation-capstone/blob/080e49752c12f5784f67014c0105b7717269a831/yf/nav/sim/convert_scene.py)、[prep_scenes.sbatch](https://github.com/fanxinyusarah/lewm-navigation-capstone/blob/080e49752c12f5784f67014c0105b7717269a831/yf/nav/slurm/prep_scenes.sbatch)）。habitat-sim 0.3.3 环境用的是队友的 `memnav-habitat-py39`。代码：[nav/sim/](https://github.com/fanxinyusarah/lewm-navigation-capstone/tree/080e49752c12f5784f67014c0105b7717269a831/yf/nav/sim)。

## 1. 渲染校准：让 Habitat 看到的画面接近 NavDP 相机

方法（[check_render.py](https://github.com/fanxinyusarah/lewm-navigation-capstone/blob/080e49752c12f5784f67014c0105b7717269a831/yf/nav/sim/check_render.py)）：取数据集里的帧，把记录的 NavDP 位姿放进 Habitat 渲染，与同一位置的真实帧比较。参照是“另一个位置的真实帧”。

| 参数 | 结果 | 依据 |
|---|---|---|
| 坐标变换 NavDP → Habitat | `rot0_mirror`（X = x, Z = −y，det = −1） | 8 种变换中唯一一个让所有帧都落在 navmesh 上（偏离 0 m）的，训练场景、val 场景都一样 |
| 相机俯角 | **−30°**（之前由外参推出的 −10.9° 不对） | 像素相关性在 −30° 有很尖的峰：0.89–0.91，−26° / −34° 分别只有 0.48 / 0.43 |
| HFOV | 68°（与 NavDP 内参一致） | 58° / 79° 都更差 |
| 光照 | 无光照 | Habitat 默认光照更差 |
| 颜色 | 按通道的单调映射 + 网格破洞填成 NavDP 的灰色 (70,70,70) | **只在训练场景 `JF19kD82Mey` 上拟合**，val 场景只用来检验 |

val 场景 `ARNzJeq3xxb`（80 帧，俯角 −30°）的 latent 余弦距离（B1 seed3072 的 encoder）：

| | 与同一位置真实帧 | 与另一位置真实帧 | 同一位置更近的比例 |
|---|---|---|---|
| 原始渲染 | 0.729 | 0.794 | 0.56 |
| **颜色校准后** | **0.042** | 0.727 | 0.88 |
| 参照：两张不同位置的真实帧 | | 0.651 | |

校准后，渲染与真实帧之间的差距比“换一个位置”小一个数量级以上，所以下面的结果主要反映模型本身，而不是渲染差异。对比图（左：真实帧，右：渲染）：[原始](val_ARNzJeq3xxb_real_vs_render_raw.png)、[校准后](val_ARNzJeq3xxb_real_vs_render_calibrated.png)。

## 2. 分支排序（4b）：在真实执行的结果上检验模型的动作排序

方法（[branch_rank.py](https://github.com/fanxinyusarah/lewm-navigation-capstone/blob/080e49752c12f5784f67014c0105b7717269a831/yf/nav/sim/branch_rank.py)）：
1. 在 val 场景的 navmesh 上采样起点和终点，最短路径距离 1–3 m。目标图在终点渲染，朝向是路径最后一段的方向。
2. 起点朝向 = 路径第一段的方向 + ±60° 的随机偏差。先走 2 步直线，得到模型需要的 3 帧历史。
3. 候选：每步是一段弧线（0.294 m，转角 ∈ {0, ±0.15, ±0.35} rad），k = 3 步，共 125 条。全部从同一个起点在模拟器里真实执行，记录走完后到目标的**最短路径距离**和是否碰撞。
4. 模型对每条候选 rollout k 步，按预测 latent 与目标 latent 的距离打分，选分数最低的。

7 个 val 场景 × 100 个 episode = 700 个 episode。模型：xysc、fs8、H=3、第 10 个 epoch，不加 B1 / 加 B1（λ=1），各 3 个 seed。

**k = 3，余弦距离**（[branch_k3_cos.md](branch_k3_cos.md)）：走完后到目标的最短路径距离，单位 m

| | 选中的候选 | 比随机多前进 | 补上“随机→最优”差距的比例 | ρ（打分与真实距离） | 选中前 10% 的比例 | 选中的会碰撞 |
|---|---|---|---|---|---|---|
| 最优（oracle） | 1.409 | 0.271 | 1 | | | |
| 欧氏距离启发式（知道坐标，作参照） | 1.421 | 0.259 | 0.96 | | | |
| 随机 | 1.680 | 0 | 0 | | 0.10 | 0.29 |
| 直走 | 1.662 | 0.018 | | | | |
| 不加 B1 | 1.693 ± 0.003 | −0.014 ± 0.003 | −0.12 | 0.01 | 0.14 | 0.30 |
| **B1** | **1.655 ± 0.006** | **+0.024 ± 0.006** | **0.07** | **0.17** | **0.24** | **0.27** |

k = 3 + MSE、k = 2 + 余弦的结论相同（[branch_k3_mse.md](branch_k3_mse.md)、[branch_k2_cos.md](branch_k2_cos.md)）。

按起点到目标的距离拆开（k = 3，余弦；“前进”= 比随机多前进的米数）：

| 起点距离 | n | oracle 能多前进 | 不加 B1 | B1 | B1 的 ρ |
|---|---|---|---|---|---|
| 1.0–1.5 m | 119 | 0.278 | −0.021 | **+0.055** | 0.30 |
| 1.5–2.0 m | 184 | 0.259 | −0.013 | +0.029 | 0.18 |
| 2.0–2.5 m | 182 | 0.277 | −0.009 | +0.006 | 0.13 |
| 2.5–3.0 m | 215 | 0.270 | −0.015 | +0.020 | 0.12 |

按场景：B1 在 7 个场景里**都**比随机好（+0.004 … +0.039 m），不加 B1 在 6 个场景里比随机略差。

## 3. 动作表示在模拟器里的比较（4b，同样的 700 个 episode）

k = 3，余弦距离；随机 1.680 m，最优 1.409 m（[branch_k3_cos_reps.md](branch_k3_cos_reps.md)，xysc 见上表）。

| 表示 | B1 | 选中的候选 [m] | 比随机多前进 [m] | ρ | 选中前 10% | 选中的会碰撞 |
|---|---|---|---|---|---|---|
| xy | 否 / 是 | 1.691 / **1.656** | −0.011 / **+0.024** | 0.02 / 0.15 | 0.16 / 0.22 | 0.30 / 0.27 |
| xyt | 否 / 是 | 1.693 / **1.655** | −0.013 / **+0.025** | 0.01 / **0.17** | 0.17 / 0.23 | 0.30 / 0.27 |
| xysc | 否 / 是 | 1.693 / **1.655** | −0.014 / **+0.024** | 0.01 / **0.17** | 0.14 / 0.24 | 0.30 / 0.27 |
| disc | 否 / 是 | 1.685 / 1.682 | −0.005 / −0.002 | 0.01 / 0.03 | 0.18 / 0.17 | 0.30 / 0.29 |
| dbin | 是 | 1.668 | +0.011 | 0.11 | 0.20 | 0.29 |

xyt 下 B1 的权重（λ = 0.1 / 0.3 / 3 只有 1 个 seed）：λ = 0 → 0.1 → 0.3 → 1 → 3 时，选中的候选为 1.693 → 1.688 → 1.667 → 1.655 → **1.636** m，ρ 为 0.01 → 0.05 → 0.12 → 0.17 → **0.20**。

- **与离线结论一致**：连续表示（xy、xyt、xysc）+ B1 最好，三者在模拟器里差别在噪声以内；dbin 次之；disc 即使加 B1 也和随机一样。不加 B1 时，所有表示都等于随机。
- λ：在模拟器里 λ = 3 比 λ = 1 稍好（离线时 λ = 3 在 k = 8 和 latent 距离的 ρ 上更差），但 λ = 3 只有 1 个 seed，需要补 seed 才能下结论。

## 4. 导航差在哪里：“完美预测器”诊断

把每条候选在模拟器里真实走完，渲染终点的真实画面，用它的 latent 打分。这相当于一个完美的预测器，排序的好坏只取决于 latent 距离这个代价本身（[branch_k3_cos_true.md](branch_k3_cos_true.md)）。

| 用什么打分 | 选中的候选 [m] | 补上“随机→最优”差距的比例（按均值） | ρ（打分与真实最短路径距离） |
|---|---|---|---|
| 随机 | 1.680 | 0 | |
| 不加 B1 的预测 | 1.693 | −5 % | 0.01 |
| B1 的预测 | 1.655 | 9 % | 0.17 |
| **真实终点画面**（不加 B1 / B1 的 encoder） | 1.586 / 1.575 | **35 % / 39 %** | 0.31 / 0.29 |
| 最优 | 1.409 | 100 % | |

预测与真实的一致程度：B1 预测的排序与“真实终点画面”的排序之间 ρ = 0.42，不加 B1 只有 0.04（它几乎不看动作）。预测的 latent 与真实终点 latent 的余弦距离中位数约 0.30，而渲染差距只有 0.04。

- **两个环节都有问题，代价函数的上限更低**：即使预测完全准确，latent 距离也只能补上约 40% 的差距；剩下 60% 是因为“画面像不像目标”不等于“离目标多近”（目标在墙后、拐角后，或者朝向不同）。预测器又把 40% 降到 9%。
- 相关证据：起点画面与目标图的 latent 距离，和真实最短路径距离的相关系数只有 0.25–0.28；模型选中的动作有 27% 会碰撞（随机 29%），训练数据里没有碰撞，所以模型不会避障。

## 5. 闭环导航（MPC，第 5 步）

方法（[mpc.py](https://github.com/fanxinyusarah/lewm-navigation-capstone/blob/080e49752c12f5784f67014c0105b7717269a831/yf/nav/sim/mpc.py)）：每一步用 CEM 优化 3 步的动作序列（300 个样本、30 个精英、3 次迭代；步长和转角限制在训练数据 99% 的范围内），代价是第 3 步预测 latent 与目标 latent 的余弦距离；执行第一步后重新规划。历史使用真实观测和实际执行的动作。
- 成功：到目标的最短路径距离 < 0.5 m（用模拟器判断是否到达）。
- 自主停止：当前画面与目标图的 latent 距离 ≤ τ 时停下。τ 对每个模型在训练场景 `JF19kD82Mey` 上用 30 个 episode 标定，val 场景不参与。
- 步数上限：2 × 起点距离 / 0.294 + 10 步。

7 个 val 场景，每个距离档 140 个 episode；模型的结果是 3 个 seed 的均值 ± 标准差（[mpc_summary.md](mpc_summary.md)）：

| 策略 | 1–2 m 成功率 / SPL | 2–4 m | 4–8 m | 1–2 m 自主停止成功率 / 停错率 | 1–2 m 每回合碰撞次数 |
|---|---|---|---|---|---|
| 随机 | 0.28 / 0.28 | 0.15 / 0.15 | 0.07 / 0.07 | | 9.7 |
| 直走 | 0.33 / 0.33 | 0.13 / 0.13 | 0.03 / 0.03 | | 9.3 |
| 不加 B1 | 0.42 / 0.39 | 0.14 / 0.13 | 0.07 / 0.07 | 0.10 / 0.29 | 7.8 |
| **B1** | **0.58 / 0.56** | **0.26 / 0.25** | **0.12 / 0.12** | **0.25** / 0.30 | 6.1 |
| 欧氏距离贪心（知道坐标，作参照） | 0.96 / 0.94 | 0.78 / 0.78 | 0.56 / 0.56 | | 1.2 |
| 最短路径贪心（oracle） | 0.99 / 0.96 | 0.96 / 0.93 | 0.95 / 0.94 | | 0.6 |

每步规划耗时约 22 ms（GPU，300 × 3 个样本）。

- **闭环的结果和开环一致，而且差距更明显**：1–2 m 时 B1 成功率 58%，不加 B1 42%，随机 28%。每一步重新规划后，即使单步排序的信号很弱，也会被不断放大。
- **距离一远就失败**：2–4 m 时 26%，4–8 m 时 12%，但仍约为随机的 1.7 倍。
- **模型自己判断“到了”很不可靠**：1–2 m 时自主停止成功率只有 25%，停错率 30%。用 latent 距离判断是否到达，和用它当代价有同样的问题。
- 碰撞很多：1–2 m 时每回合约 6 次（oracle 0.6 次），模型不会避障。

## 结论

1. **动作表示**：离线和模拟器的结论一致。连续表示（xy / xyt / xysc，三者等价）+ B1 最好；离散表示（disc）即使加 B1 也和随机一样。比动作表示更关键的是 B1：不加 B1 时所有表示都等于随机。
2. **能不能导航**：近距离可以，但不可靠。1–2 m 时成功率 58%（随机 28%），4–8 m 时只有 12%。
3. **为什么差**：主要是代价函数，其次是预测器。即使预测完美，latent 距离也只能补上约 40% 的差距；预测误差又把它降到约 9%。另外，训练数据只有专家轨迹，没有碰撞样本。
4. **下一步建议**：(a) 换掉“latent 距离 = 离目标多远”这个假设，学一个距离 / 可达性函数，或者使用中间子目标；(b) 在训练数据里加入非专家动作和碰撞，或者在模拟器里收集；(c) λ = 3 补 seed。

## 局限

- 颜色映射只在一个训练场景上拟合；渲染校准只在一个 val 场景上做了详细检查（其余 6 个 val 场景用同一套设置）。
- 候选和 CEM 只覆盖训练动作分布内的弧线，没有原地转身或停止（训练数据里也没有）。
- 成功判定使用模拟器的真实位置；模型的自主停止单独报告。
- 每个距离档每个场景 20 个 episode，按 7 个场景合计 140 个。
